Introduction

In general, datsets are made of variables of different data types. The value of the data for these variables can take values that are discrete, continuous, or both (semi-continuous). When a variable includes both discrete and continuous values (components), it is referred to as semi-continuous data type. The choice of a model to represent the distribution of a variable in a dataset is driven by the type of data contained within that variable. For example, if the variable’s data type is continuous, we can use a normal distribution model to represent its distribution. If the variable’s data type is discrete, we can use a Poisson distribution model. However, if the data contained within the variable include both discrete and continuous components, we can use a semi-continuous mixture model to represent its distribution.

In this project, we use the weather dataset which includes a varible for maximum temperature (tmax), and a variable for precipitation (pr). The maximum temperature variable is continuous, as it can take on any value within a certain range. The precipitation variable on the other hand provides the amount of rainfall in a given location and time, reflecting the possibility of both no precipitation (discrete) and positive precipitation (continuous) values, making the data type of this variable semi-continuous.

The main objectives of this project are:

  1. Model the conditional distribution of precipitation given maximum temperature (pr | tmax).

  2. Answer the following scientific questions:

    • Does the probability of rain depend on the temperature?
    • Does the amount of rain depend on the temperature?
Part 1: Setup

In this first step of the project, we load all necesary libraries, load and explore the weather dataset, prepare it for analysis according to the directions assigned to our group (Group 2), and then define a custom loss function for a semi-continuous gamma mixture model.

1. Data Exploration and Preparation

We first load the dataset and explore its structure and dimensions. - Load the dataset:

The weather dataset contains daily weather data from January 1, 1951 to December 31, 2014. Its structure has 7 variables and 584,000 observations. The variables are: time, latitude, longitude, maximum temperature (tmax), precipitation (pr), month, and location. The dataset is in long format, with each row representing a single observation for a specific location and time.

The month assigned to our group (Group 2) was June. We first subset the dataset to include only the observations for June and then convert all temperatures from Kelvin (K) to degrees Celsius (°C). We also set all precipitation values less than 0.01 to 0.

The resulting subset dataset contains 48000 observations, comprising 7 variables.

We split the subset dataset into training and testing sets, we will use the data from 1961 to 2000 as the training set and the data from 1951 to 1960 and 2001 to 2014 as the testing set. The training set contains 30000 observations, while the testing set contains 18000 observations.

The split is as follows:

- Training set: 30000 / 48000 = 0.625 = 62.5%
- Testing set: 18000 / 48000 = 0.375 = 37.5%

This split is approximatly 60% for training and 40% for testing, allowing us to train our model on a substantial amount of data while reserving a significant portion for evaluating its performance on unseen data.

2. Custom Loss Function for semi-continuous gamma mixture:

Now that our dataset is ready for analysis, we define a custom loss function for a semi-continuous gamma mixture model. This loss function will be used to fit the model to the training data and evaluate its performance on the testing data.

  • The Loss Function for semi-continuous gamma mixture model:

Taking into account the mixture model:

\[Y\ |\ X, \theta \sim \ \pi_0 \ + \ (1 - \pi_0)Gamma(\alpha, \beta)\]

Here, \(\theta = (\pi_0, \alpha, \beta)\), hence the parameters to be estimated were therefore \(\pi_0\), \(\alpha\) and \(\beta\). Here, \(\pi_0\) represents the probability that it will not rain, whereas the \(Gamma\) distribution portion of the formula models precipitation in terms of temperature if it rains. \(\alpha\) and \(\beta\) are parameters of the \(Gamma\) distribution, relevant for estimating the mean precipitation.

Importantly, the \(Gamma\) portion of the formula is only relevant if it rains, hence the log-likelihood function must correctly account for that. The log-likelihood function is thus:

\[\begin{equation*} l(\theta|Y) = \begin{cases} \sum\log\pi_0 & \text{if } y = 0 \\ \sum\log(1-\pi_0)\ + \ \sum\log(Gamma(\alpha, \beta) & \text{if } y > 0 \end{cases} \end{equation*}\]

The script for this custom loss function takes in the predicted values and the true values, and calculates the negative log-likelihood for the semi-continuous gamma mixture model. The function first extracts the observed precipitation values and creates a binary variable indicating whether it rained or not. It then extracts the predicted probability of no rain, as well as the predicted shape and scale parameters for the gamma distribution. Finally, it calculates the log-likelihood for the semi-continuous gamma mixture model and returns its negative value, which is equal to (-ll) the loss that will be minimized during model fitting.

when fitting the models, the validation argument is set to 0.2 which means that 20% of the training data is used for validation during training. This allows us to monitor the model’s performance on unseen data and helps to prevent overfitting. The batchsize argument is set to 50, which means that the model is trained on mini-batches of 100 observations at a time. This can help to speed up training and improve convergence.

epochs argument is set to 50, which means that the model is trained for 50 iterations over the entire training dataset. This can help to ensure that the model has enough time to learn the underlying patterns in the data.

to balance the batchsize and epochs arguments, we can adjust the batchsize to a smaller value (e.g., 25) and increase the number of epochs (e.g., 100). This will allow the model to see more data during training while still allowing for enough iterations to learn the underlying patterns in the data.

cbind(y, y, y) ~ x is used to specify the model formula for the neural network. It indicates that we want to predict three outputs (y, y, y) based on a single input variable (x). This allows us to fit a multi-output neural network model that can predict multiple outputs simultaneously.

the three outputs (y, y, y) represent the three parameters of the semi-continuous gamma mixture model: the probability of no rain (pi0), the shape parameter of the gamma distribution (alpha), and the scale parameter of the gamma distribution (beta). By predicting all three parameters simultaneously, we can capture the complex relationship between maximum temperature and precipitation in a single model.

Part 3: Model Validation

To evaluate the model’s ability to predict whether it will rain or not (the probability of not raining \(\pi_0\)), the observations in the testing set with precipitation superior to 0 were coded as 1, while the others were left as 0. \(\pi_0\) predictions for each data point in the testing set were obtained and plotted in a histogram.

1. Predicting wheter it rains:

The estimates of \(\pi_0\) are concentrated around very high values, which agrees with the observation that in most days in the testing set it did not rain.

To assess the model numerically, we used the Brier score, defined by the formula

\[BS = \frac{1}{n}\sum_{i=1}^n(f_i-o_i)^2\] where \(f_i\) is the predicted probability, \(o_i\) is the actual outcome (0 or 1) and n is the dataset size. In this case, n is the testing set size, which is 1200.

# Brier Score
# The probability of raining (1 - pi_0) is expected to be pretty low, as most data points are 0

Conversely, to evaluate how well the model predicted the amount of rain in the days that rainfall was observed, we first subset the testing set to only rainy days.

We proceeded to calculate the mean rainfall from the \(\alpha\) and \(\beta\) parameters of the \(Gamma\) distribution, per the following formula:

\[\mu = \frac{\alpha}{\beta}\] These mean values were then plotted against the actual observed rainfall values:

The model seems to perform generally well considering that the larger values in the x-axis are few and sparse, with the larger cloud of points indicating a general agreement between predicted and real values, with the larger values exhibiting outlying behavior.

The root mean-squared error (RMSE) was used to diagnose the model’s ability to predict the amount of rainfall. The RMSE is calculated via the following formula:

\[RMSE = \sqrt{\frac{1}{n}\sum(y_i-\hat{y_i})^2}\] where \(y_i\) are the observed values and \(\hat{y_i}\) are the predicted values for rainfall, in this case.

The resulting value for the RMSE was 3.93. Given the scale of the data, this value is not particularly low, however some reasonably outlying behavior was observed for some data points, which likely inflated some of the residuals, driving up the RMSE.
